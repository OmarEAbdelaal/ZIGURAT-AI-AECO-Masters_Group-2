# Results

Everything here is **generated by code**, never hand-edited. `src/train.py` writes the
metrics; `src/evidence.py` and `src/error_analysis.py` write the images and the tallies.
Re-running notebooks `02` and `03` refreshes the whole folder.

That matters for a reason beyond tidiness: a metrics table typed into a README drifts from
the run that produced it the first time anyone re-trains, and nobody notices. A generated
one cannot.

> ⚠️ **Current contents are from the VERIFICATION run** on the procedural dataset
> (`DATASET_SOURCE="synthetic"`). They prove the pipeline executes end to end without
> credentials. They are **not** evidence of real-world façade detection performance.

## Layout

| Path | What it is |
|---|---|
| `metrics/metrics.md` | Human-readable metrics table with the reproduction parameters |
| `metrics/metrics.json` | Machine-readable: metrics, dataset health, environment, timings |
| `metrics/metrics_per_class.csv` | Per-class P / R / mAP50 / mAP50-95 |
| `metrics/error_analysis.json` | Full error tally and the ranked worst cases |
| `curves/results.png` | Loss curves + metric progression — the vitals check |
| `curves/confusion_matrix_normalized.png` | Which classes get mixed up |
| `curves/PR_curve.png`, `P_curve.png`, `R_curve.png`, `F1_curve.png` | Threshold behaviour |
| `curves/results.csv` | Per-epoch raw numbers |
| `curves/labels.jpg` | Label distribution — class balance and box-size spread |
| `evidence/annotations/` | 5 ground-truth renders — the label contract as applied |
| `evidence/validation/` | 10 validation predictions + `manifest.json` with the VE read-out |
| `evidence/new_images/` | 5 predictions on unseen images — the honest test |
| `evidence/errors/` | Worst FP / FN / class-confusion / localization-drift crops |
| `weights/best.pt` | The trained model. `best.pt`, never `last.pt` |

## Reading the evidence renders

Boxes use the Group 02 design-system series colours, consistently across every image:

| swatch | hex | class |
|---|---|---|
| 🟦 | `#1C60F3` | `window` |
| 🟩 | `#41CF97` | `curtain_wall` |
| 🟪 | `#7B4FE0` | `door` |
| 🟧 | `#DD6B20` | `balcony` |
| 🟦 | `#17A2B8` | `louvre_screen` |

In `evidence/errors/` the colour coding changes to encode the error instead:
**green** = ground truth · **red** = a wrong prediction · **orange** = a missed instance.

## The VE read-out in `manifest.json`

Each prediction manifest carries the two numbers the FMP's VE engine consumes:

```json
"ve": {
  "glazed_fraction_of_frame": 0.2841,
  "envelope_cost_index": 214.7,
  "counts": {"window": 18, "curtain_wall": 1, "balcony": 4},
  "basis": "uncalibrated pixel areas — relative screening signal, not a take-off"
}
```

That `basis` string travels with every output deliberately. These are **pixel-domain**
figures from a single uncalibrated image: a relative signal for comparing design options,
never square metres and never a quantity take-off. Removing the caveat from the data
structure would be the first step towards someone quoting the number without it.
